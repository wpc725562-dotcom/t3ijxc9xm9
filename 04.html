两个必须记住的污染机制

①「复盘」是股市与考公的高频词。B站搜索会把「复盘」和财经/公考内容强绑定，你在它后面接什么都会被冲掉。同理禁用：经验、心得、攻略（后两者还行，但会混入非技术内容）。

②「应届生」会把搜索拉到全专业。这个词本身没有技术指向，机械、财会、土木的简历教程会一起涌进来。换成 计算机 / 程序员 / 校招 当主语。

2.2 八条搜索思路

  1. 主语用「计算机 / 程序员 / 校招」，不用「应届生」。技术指向越明确，命中越准。
  2. 关键词拆成「对象 + 动作」两段。「项目 + 亮点怎么写」「简历 + 项目经历」「项目 + 怎么讲」。连写成一个词（如「简历项目」）反而会丢掉一半结果。
  3. 按 UP 主搜 > 按主题搜。探测发现同一批高质量内容会在多个关键词下反复出现 —— 说明产出集中在少数几个号，直接进主页最省时间。
  4. 排序用 totalrank（综合排序）。默认排序噪声极大，这是之前就验证过的。
  5. 警惕课程引流号。标题里出现这些短语的，基本都是「批量搬运 + 引流卖课」，质量必须实测：
    练完即可就业 活该你拿offer 少走99%的弯路 已经替大家付费了 建议码住
    本次探测中「15 个 / 16 个 Agent 实战项目」这一族标题高度雷同，是同一个模板的批量产出。
  6. 看发布日期。AI Agent / LLM 方向只看 2026 年以后。2024 年的 LangChain 教程今天跑不起来，学完反而是负资产。
  7. 用收藏率 / 投币率判断质量，但要知道偏差。收藏率 = 「以后还要再看」的强意愿，投币是 B 站最高成本行为。但体量大的课程会被系统性低估（104 集的课用户当教材用，不会收藏），单集爆款会被系统性高估。
  8. 交叉验证。同一条建议（比如「别做商城秒杀」）如果被 3 个以上互不相关的 UP 主说过，才值得当结论；只有 1 个人说，当观点听。

3. 值得做的项目：三层分级 先说什么不要做

✗ 淘汰层 —— 做了是负资产，不是零资产

1. 教程复刻型。跟着视频做的商城、秒杀、外卖点餐、后台管理系统。
理由：面试官一天看几十份简历，这些是同一批项目。更要命的是，一旦被追问「这个和教程里的区别是什么」，答不上来就当场掉分 —— 它证明的不是能力，是「会跟着做」。

2. 纯 CRUD 管理系统。增删改查 + 权限 + 分页。没有非平凡的技术决策。

3. 已经被打上标记的培训班项目。黑马点评、瑞吉外卖、苍穹外卖这一类，面试官已经能一眼认出来。注意：这些内容本身质量不差，但作为「你的项目」是负资产 —— 你要学可以学，别往简历和 GitHub 上放。

4. 只有 UI 的项目。去掉界面后什么都不剩的，不算工程能力。

○ 及格层 —— 不扣分，但也不出彩

1. 有真实使用者的自用工具。哪怕使用者只有你自己，只要它真的在被用、有真实数据流过，就比教程复刻强。

2. 给真实开源项目提的 PR。被 merge 的 bug fix 或小 feature。这证明你能读别人的代码、能遵守协作规范 —— 这是应届生最缺的证据。

3. 有评测的 Agent demo。做了 Agent，并且能说出它在某类任务上的成功率。

★ 加分层 —— 差异化在这里

1. 解决真实痛点，且有外部使用者。「真实痛点」= 别人也在疼的问题，不是你为了做项目造出来的需求。

2. 有可量化的工程指标。准确率、延迟、成本、处理规模 —— 任意一个能用数字说出来的维度。

3. 有技术纵深。不是调 API 拼起来的，中间有你自己设计的东西（算法、协议、调度策略、数据模型）。

4. 选题方向 对准 AI Agent / LLM 应用岗

下面按「对你的岗位价值」排序。核心判断：做「给 AI 用的工具」，比「用 AI 做的东西」更值钱。

方向 1 · Agent 评测与可观测（最稀缺，推荐）

做什么：针对某一类任务（比如「工具调用正确率」「多轮任务完成率」）构建自动化评测集 + 打分器 + 轨迹回放调试器。

为什么值钱：Agent 领域最难的不是「让它跑起来」，而是「证明它变好了」。绝大多数人做的 Agent 项目都停在 demo，说不出好坏。能建评测体系的人极少 —— 而这是团队真正需要的能力。

可量化指标：评测集规模、任务成功率、打分器与人工标注的一致率。

方向 2 · 给 Agent 用的基础设施

做什么：工具调用的沙箱执行环境、token 成本归因分析、上下文压缩策略对比、多 Agent 消息路由。

为什么值钱：这是「造 Agent 的 Agent」。写这类项目说明你不只会用框架，还理解框架的瓶颈在哪。

可量化指标：成本下降百分比、延迟改善、支持的工具数量。

方向 3 · RAG 的深水区（避开「知识库问答」）

做什么：不要做又一个「上传 PDF 然后问答」。做检索质量诊断：切分策略对比实验、召回率归因、长文档结构感知切分。

为什么值钱：「知识库问答」已经烂大街（实测 B 站一搜一大把）。但「说清为什么这个 chunk 策略比那个好」是稀缺的。

可量化指标：召回率 / 命中率对比表。

方向 4 · 信息资产化管道（你已经在做了）

做什么：把「非结构化内容 → 结构化可检索资产」的链路做成通用工具。你本地的 B 站提取链路就是这个方向的原型。

为什么值钱：它天然带真实规模和真实脏数据（802 集、4.7% 损坏率、46h39m 冗余识别）—— 这些都是可量化的故事，不是编出来的。

可量化指标：处理规模、损坏检出率、人工工时节省。

方向 5 · 日语 × AI（唯一同时推进门槛项和加分项的方向）

做日语学习用的 LLM 工具。理由：日语 N2 是你唯一的红灯门槛，而「造工具」是你最有动力的行为模式。这是唯一一个「造工具」和「推进门槛」重合的交叉点。

注意纪律：这个工具必须真的被用来学日语，否则它就退化成拖延。判据很简单 —— 工具做完后一个月，你的日语进度有没有动。

5. 取舍标准 5 条硬指标 + 3 道检验

5.1 五条硬指标 —— 任一条不过就砍掉这个选题

#指标判据
1能用数字说明它好吗准确率 / 延迟 / 成本 / 处理规模，任意一个能给出具体数值。给不出 → 这个项目没有可讲述的成果。
2陌生人 5 分钟能跑起来吗README 首屏有一行命令或 Docker；不需要「先装 3 个环境、配 5 个 key、改 8 处配置」。
3有别人提过需求吗有人开过 issue、发过邮件、在评论区问「能不能加 X」。外部需求是「这不是自娱自乐」的唯一证据。
4你是唯一能维护它的人吗项目里有非平凡的设计决策（为什么这样切分、为什么这样调度）。如果换个人看两小时就能接手 → 没有技术纵深。
5面试官能当场验证吗有可复现的输入输出示例、测试用例、或线上 demo。只有截图 = 无法验证 = 不加分。

5.2 三道检验 —— 用来识别「负资产」

检验一：教程差异检验

面试官问「这个和教程里的区别是什么」，你能不能在 30 秒内给出具体的不同点？答不上来 → 负资产。

检验二：去 UI 检验

把界面去掉，还剩下什么？如果剩下的只是「调用了几次 API、存了几张表」→ 负资产。

检验三：三分钟自述检验

不看代码，你能不能在 3 分钟内说清四件事：解决什么问题 → 为什么难 → 你怎么解的 → 效果数字。
卡在任何一步，说明这个项目你还没真正「拥有」它 —— 那你写进简历也只是在赌面试官不问。
