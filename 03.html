为什么推荐 eladmin-mp 而不是另外两个

① 你的任务描述是「完整吃透」，这三个字决定了选择。

「吃透」的反面不是「不会用」，而是「跑通了但讲不出为什么」。717 个文件的 mall 在 6 周内只能做到「能跑 + 讲主干」，这不叫吃透。305 个文件的 eladmin 是可以真读完的 —— 读完 305 个文件带来的掌控感，比跑通 717 个文件更有价值。

② MyBatis-Plus 比 JPA 更对口。

原版 elunez/eladmin（21,909 star）用的是 Spring Data JPA，而日本 SIer/受託開発 现场和中国互联网公司都以 MyBatis / MyBatis-Plus 为主。作者另开了 eladmin-mp（MyBatis-Plus 版），建议直接用这个。代价 mp 版 star 只有 686，社区资料比原版少。

③ 后台管理系统是日本现场最典型的业务形态。

eladmin 的形态就是「RBAC 权限 + 多模块 + 前后端分离后台」，这正是日本受託開発 里最常见的交付物。mall 的电商业务在日本现场反而不是主流。

④ 苍穹外卖只在一种情况下选：你必须有个人带你走。

如果你自学时容易卡住、需要有人讲每一步，那 199 集视频的价值是压倒性的 —— 但要接受三个代价：① 没有官方仓库，代码靠公众号领；② Spring Boot 2.x 技术栈偏旧；③ 无许可证，不能作为你自己的作品发出去。

如果你更想要「简历上的高星背书」

那就选 mall，但要把 P0 的目标从「吃透」下调为「跑通 + 能讲清主干 + 改 3 处」。这是诚实的取舍 —— 别在 6 周里假装自己吃透了 58 MB 的工程。

03P1 三选一对比

最重要的一个核实结果

三个候选里，有两个在 GitHub 上没有官方仓库。

  • 《硅谷AI链习室》（尚硅谷，B 站 87 集 / 22:48:02）：简介写的是「关注公众号：尚硅谷教育，回复"AI链习室"免费获取」→ 无公开仓库。GitHub 上唯一的复刻是 CelestialVisionary/studyforge，5 star。
  • 《心理健康助手》（B 站 82 集 / 22:29:25）：简介列了完整技术栈但没给任何代码链接 → 无公开仓库。
  • yu-ai-agent：✅ 有官方公开仓库，2,698 star，可直接 git clone。

这个差别不是小事：能读代码、能改代码、能 fork 出自己的一版，是学习 AI 应用最核心的杠杆。只能看视频的话，你永远停在「看懂了」而不是「会写了」。

为什么推荐 yu-ai-agent

① 它是唯一能让你「动手改」的选项。读代码 → 改代码 → 讲出改动理由，这条路只有有仓库才走得通。另两个候选你只能看视频，而看视频会产生一种「我懂了」的错觉 —— 直到面试官问「那你自己实现过吗」。

② 它一次性覆盖了 AI 应用岗的四个核心概念。RAG（知识库检索增强）、MCP（模型上下文协议）、Agent（ReAct 自主规划）、工具调用 —— 这四个词现在几乎是 AI 应用岗 JD 的标配。而且它同时用了 Spring AI 和 LangChain4j 两个框架，面试时你能对比着讲「为什么两个都用」，这是加分项。

③ 287 KB 的体量是优点不是缺点。它意味着这个仓库是「纯粹的教学代码」，没有塞素材、没有二进制垃圾，你可以快速读完。对比之下，苍穹外卖复刻是 132 MB、天机学堂复刻是 127 MB —— 那些体积里大部分不是代码。

④ 一个必须知道的代价：完整视频教程要付费。仓库代码是公开的，但鱼皮的全程直播讲解在「编程导航」会员里。所以你的路径会是「读公开代码 + 自己查文档」。如果你预算紧张且必须有人讲，那就退到「心理健康助手」——82 集免费视频 + 完整技术栈，代价是没有代码仓库，得走公众号领。

注意：yu-ai-agent 无许可证

它的仓库没有 LICENSE 文件。学习、本地改造没问题，但不要把它 fork 后当作自己的作品公开发布。如果你要发到自己的 GitHub，请明确标注来源并做实质性改造。

怎么选

默认选 mall-swarm，三个理由：① star 是天机学堂的 36 倍，社区资料和踩坑记录多得多；② 技术栈是 2026 年最新的（Spring Cloud 2025 + Boot 3.5 + JDK 17），天机学堂复刻停在 2024-07；③ 有 Apache-2.0 许可证。

但如果你更看重「面试时怎么讲」，天机学堂有个别人没有的东西。它的 README 不是项目介绍，而是一份面试问答稿——「面试官追问：那你知道 Redisson 分布式锁原理吗？」然后给出完整回答。这种把「技术实现」和「怎么讲出来」绑在一起的材料很少见。

还有第三种选择（一箭双雕）：finch04/online-mooc 是《天机学堂》的升级版 —— 332 star、Apache-2.0、2026-05 仍活跃，技术栈是 JDK 17 + Spring Boot 3 + Spring Cloud Alibaba 2021 + Langchain4j + Qdrant + Sentinel + Seata + InfluxDB + SkyWalking + Prometheus + Grafana。它同时含微服务和 AI，如果你想让 P2 顺带把 P1 的 AI 能力再练一遍，这个是最优解。

一个被低估的学习机会

如果你 P0 选了 mall、P2 选了 mall-swarm，你会拿到一对同源的单体版和微服务版。这比学两个不相干的项目有价值得多 —— 你可以逐模块对照「同一个功能，单体怎么写、微服务怎么拆」，然后回答那个面试必问的问题：「为什么这里要拆成微服务？」能讲清取舍，比会用 Nacos 值钱。

从数据里读出的两条

① 秒杀的参考实现比商城少一个量级，且几乎全部停更。商城类最高 84.8k star 且 2026-09 仍在推送；秒杀类最高 26.6k，README 自己写着「停更」，其余多数停在 2021–2022。

② 秒杀类 7 个仓库里只有 1 个有许可证。这意味着你读到的实现大多不能直接复用 —— 但反过来说，这也正是它能产生差异化的原因：没有成熟参考，你自己做的方案就是你自己的。

为什么还是选秒杀

① 技术点和 P0–P2 完全不重复。商城你已经做过两遍了（P0 的后台 + P2 的微服务电商）。再做一遍商城，边际收益接近零。而秒杀逼你处理的是另一类问题：库存原子扣减、一人一单、防超卖、限流削峰、缓存与数据库一致性。

② 这些技术点是面试高频，日本现场也用得到。日本 SIer 虽然以业务系统为主，但「高并发下的数据一致性」是通用能力，而且这是能让你在面试里从「做过 CRUD」变成「处理过并发问题」的分水岭。

③ 参考实现少，反而是机会。正因为没有 84.8k star 的成熟参考，你「读三个实现 → 对比方案 → 自己写一版」的过程才真的是在做研究，而不是在抄。这也正好承接你要的「对比分析」。

但必须换一种做法。不要「跟着一个课程再抄一遍秒杀」。正确姿势是：先读三个开源实现的限流/缓存/队列方案，输出对比表，再自己实现核心链路。这样 P3 的产出是一份「方案对比 + 我的选择及理由」，而不是第四个练手项目。

P0

完整吃透一个 Spring Boot 单体项目

第 1–6 周 ｜ 选定：eladmin-mp（备选：苍穹外卖 / mall）

阶段目标：不只是跑通，而是能画出模块依赖图、能讲清一次请求的完整链路、能独立加一个业务模块。

W1
跑通 + 摸清地形
环境搭建（JDK / MySQL / Redis / Node）、前后端跑通、手画模块依赖图（5 个模块各自负责什么、谁依赖谁）、列出所有技术栈清单并逐个查清用途。
W2
认证与鉴权链路
JWT 签发/校验、Spring Security 过滤器链。产出：一次登录请求从进网关到返回 token 的完整时序图（自己画，不许复制）。
W3
权限模型（这个项目的核心）
RBAC、接口级权限、数据级权限、菜单动态路由。产出：能回答「一个请求怎么被判定有权/无权」的全过程。
W4
数据层
MyBatis-Plus 的 CRUD、条件构造器、分页、代码生成器、事务。产出：手写一个完整业务模块的增删改查（不生成，手写）。
W5
工程化能力 + 第一次改造
Redis 缓存与 Redisson、异步线程池、全局异常处理、日志、限流。改造任务：加一个自己的业务模块（比如「学习打卡记录」），走完整链路。
W6
部署 + 复盘 + 写面试稿
打包部署；写一份自己的 README（架构图 + 模块说明 + 你改了什么 + 你的取舍理由）；整理 10 个可能被追问的问题并写下答案。
P0 验收标准（全中才算过）
  • 能不看代码画出模块依赖图
  • 能讲清「一次带权限的请求」的完整链路（≥5 分钟）
  • 自己加的模块能跑通，且能说出每一行为什么这么写
  • 有一份自己写的 README，不是复制粘贴的
  • 10 个追问问题里有 ≥7 个能答上来
P1

完成一个 Java + AI 项目

第 7–12 周 ｜ 选定：yu-ai-agent（备选：心理健康助手 82 集免费视频）

阶段目标：能讲清 RAG 的完整链路和 Agent 的工具调用循环 —— 这两件事是 AI 应用岗面试的分水岭。

W7
AI 基础概念 + 跑通最小闭环
LLM 调用、Prompt、Token、上下文窗口、结构化输出。跑通一个最小 Spring AI 对话 Demo。产出：能解释「一次大模型调用发生了什么」。
W8
Spring AI 核心机制
ChatClient、Advisor 拦截链、对话记忆（多轮上下文怎么存）、结构化输出。产出：自己写一个自定义 Advisor。
W9
RAG 全链路（最重要的一周）
文档加载 → 切分策略 → 向量化 → PGvector 存储 → 相似度检索 → 增强生成。产出：一张 RAG 全链路图 + 能讲清「为什么切分策略会影响效果」。
W10
MCP 模型上下文协议
理解 MCP 解决什么问题（让模型访问外部工具/数据）。读 yu-image-search-mcp-server 的实现，改造或自己写一个 MCP 服务。
W11
ReAct Agent
工具调用循环、自主规划、失败重试。理解 ReAct（Reason + Act）和普通函数调用的区别。产出：能讲清 Agent 怎么决定「下一步调用哪个工具」。
W12
改造 + 部署 + 写面试稿
做一个自己的改造（换业务场景 / 加一个工具 / 优化检索）。部署上线。产出：RAG 调优笔记 + Agent 讲解稿。
P1 验收标准
  • 能白板画出 RAG 全链路，并说出每一步的可调参数

07时间闸门与日语约束

这个计划最重要的一节

20 周项目计划最大的风险不是「做不完」，而是做完了、日语没动。写代码当天就有反馈，学日语要三个月后才看到效果 —— 这个引力差会让项目不断挤占日语时间，而且每一次挤占都有「就今天例外」的合理理由。

三条硬规则

规则一：日语时段不可侵占，且要前置。

把日语放在每天的第一个时段，而不是「项目做完还有精力再学」。理由很简单：项目是无限可投入的（永远有东西可以优化），日语是有固定课时的。用有边界的任务去挤占无边界的任务，结果必然是有边界的那个消失。

规则二：每档设硬截止日期，到点砍功能收尾，不延期。

P0 第 6 周末、P1 第 12 周末、P2 第 16 周末、P3 第 20 周末。到点没做完 → 砍掉未完成的功能，写复盘，进入下一档。「顺延一周」是最容易发生的失控方式，因为它看起来只是个小让步。

规则三：P2 / P3 是条件触发，不是计划内。

它们不在你的「必须完成」清单里。解锁条件：日语进度达标 + 上一档按时完成。两个条件都满足才启动。这样即使 P2/P3 全部砍掉，你仍然完成了「一个能讲透的 Java 后端项目 + 一个 Java+AI 项目 + 日语推进」——这已经是一份完整的求职准备。
